\section{Introdução}
O presente experimento tem como objetivo introduzir os alunos ao processo de projeto e implementação de sistemas digitais utilizando VHDL como Linguagem de Descrição de Hardware (HDL). A atividade busca promover o treinamento prático em modelagem, análise e síntese de circuitos digitais, utilizando o ambiente de desenvolvimento \textbf{Intel Quartus Prime v24.1} como ferramenta principal.

Como aplicação prática, propõe-se a implementação de um processador Multiciclo compatível com a ISA RV32I reduzida, contendo as instruções:\cod{add}, \cod{sub}, \cod{and}, \cod{or}, \cod{slt}, \cod{lw}, \cod{sw}, \cod{beq}, \cod{jal}, \cod{jalr}, \cod{addi} e \cod{lui}. Essa abordagem permite compreender o funcionamento interno de um processador Multiciclo, ou seja, a unidade de controle, o caminho de dados e o fluxo de instruções aplicados na divisão de instruções em etapas.

A implementação será validada por meio de simulação funcional e temporal, com análise de \textit{timing} e frequência máxima de operação, permitindo compreender, de forma integrada, o funcionamento de uma arquitetura RISC-V.

\subsubsection{Tarefa I}
\begin{tcolorbox}[title=Enunciado, colback=blue!5!white, colframe=blue!75!black]

Na Arquitetura Von Neumann, dados e programas na mesma memória, implica que a memória de código deve ser gravável do mesmo modo que a memória de dados. Logo basta colocar o controle igual das duas memórias, apenas selecionando, pelo endereço, qual dos dois blocos deve ser utilizado. Explique como isso foi feito no seu processador. 
\end{tcolorbox}

Como utilizamos a mesma memória do Uniciclo, dividida em \cod{ramI}, de instruções e \cod{ramD}, de dados, de fato, ainda há separação entre dados e memória. A estratégia para unificar a memória foi criar uma entidade \cod{unifiedMemory}, que cria uma abstração de Arquitetura Von Neumann para o resto do sistema - o processador só vê um bloco de memória, que tem como entradas um endereço, um dado, o \textit{clock} e duas entradas de controle: \cod{memWrite} e \cod{memRead}.

Dentro dessa unidade, então, verifica-se se o objetivo é acessar instruções ou dados por meio do bit 28 do endereço. Esse mesmo bit é utilizado para, por meio de operações \cod{and} envolvendo ele e os sinais de controle, decidir qual memória de fato é acessada e, via atribuição condicional, decidir se a saída da memória unificada será a da memória de dados ou de instruções. 

\subsubsection{Tarefa II}
\begin{tcolorbox}[title=Enunciado, colback=blue!5!white, colframe=blue!75!black]

O bloco de memória IP utilizado pelo Quartus necessita 2 ciclos de clock para acesso. Explique que alterações podemos fazer no Diagrama de Estados de modo a otimizar esse acesso. 
\end{tcolorbox}

Para o acesso ao bloco de memória, são necessários dois ciclos de clock. Sabendo que o acesso se refere tanto à leitura quanto à escrita, é possível realizar algumas mudanças no diagrama de estados do Bloco de Controle de forma a otimizar esse acesso.

Anteriormente, no projeto do Processador Uniciclo, a resolução para o dado problema foi dividir o clock em dois: um clock exclusivamente para a memória e um outro clock para o resto da CPU. Seguindo essa ideia, o clock da memória, ao ser configurado para ter uma frequência duas vezes maior que a frequência do processador, foi capaz de suprir a sua necessidade por dois ciclos sem interferir no funcionamento da CPU.

Agora, no projeto do Processador Multiciclo, não é mais necessário dividir o clock em dois. Isso porque iremos otimizar o acesso à memória a partir do Bloco de Controle, especificamente, a partir do seu diagrama de estados. Para realizarmos essa otimização, primeiro, é necessário identificar quais são os estados que realizam o acesso à memória. Como esse acesso é caracterizado tanto pela escrita quanto pela leitura, basta observar quais estados ligam qualquer um dos sinais \cod{memRead} ou \cod{memWrite}. Assim, foram identificados os seguintes estados:

\begin{itemize}
    \item Fetch: É o estado inicial do diagrama, ou seja, o primeiro a ser executado. Esse estado liga o sinal \cod{readMem} para que a próxima instrução seja lida pelo bloco de memória;
    \item MemRead: É o estado caracterizado por ser a quarta etapa de uma instrução ``load''. Esse estado liga o sinal \cod{LeMem} para que o bloco de memória leia o dado escolhido para que esse dado seja escrito em um registrador no próximo estado;
    \item MemWrite: É o estado caracterizado por ser a quarta e última etapa de uma instrução ``store''. Esse estado liga o sinal \cod{memWirte} para que o bloco de memória sobrescreva o dado escolhido.
\end{itemize}

Identificados os estados, podemos implementar a seguinte otimização: criar novos estados iguais a esses (ou seja, com as mesmas saídas), posicionando estes imediatamente antes daqueles no diagrama de estados. Assim, segue um exemplo: o diagrama de estados terá, como o estado inicial, a ``cópia'' do Fetch (que ativa os mesmos sinais que o Fetch ``original'', incluindo o sinal \cod{memRead}) e, quando chegar a batida do clock, o novo estado será o próprio Fetch ``original''.

Dessa forma, estaremos garantindo que os estados que acessam a memória utilizem dois ciclos, sem, ao contrário do uniciclo, que seja necessário retardar o tempo de clock do CPU para que ele seja corresponde ao de dois clocks de memória. Destarte, poder-se-á utilizar a maior frequência de clock possível.

Apesar dessa ser uma otimização relevante, ela não foi realizada por este grupo, pois, quando percebemos essa possibilidade, o projeto do controle já estava demasiado avançado, de forma que não era viável reiniciá-lo considerando os novos fatos.

A abordagem para implementar a lógica de próximo estado é um pouco diferente; não minimizaremos equações nem nada do tipo. O Registrador de Deslocamento é capaz de fazer cinco operações: \textit{shift left(L)}, \textit{shift left(R)}, \textit{load(D)}, \textit{hold} e \textit{reset}, em que a variável entre parenteses representa o argumento necessário para aquela operação (L: o bit que entra a esquerda no \textit{shift left}, R: o bit que entra a direita \textit{shift left}, D: o vetor de quatro bits que substitui o estado atual no \textit{load}). O \textit{hold} e o \textit{reset} não foram utilizados nesse projeto.
